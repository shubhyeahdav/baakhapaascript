# Every page on a phone — 2026-09-08

`WORK_LIST.md` Day 3. Day 2 fixed the editor header by hand, having measured it
by hand, and left eight pages nobody had looked at. This is the pass over those
eight, and the script that makes the next pass cost a minute instead of a day.

Run it yourself, against dev servers that are already up:

```
cd baakhapaa-frontend && node scripts/responsive-audit.mjs
node scripts/responsive-audit.mjs --width 320
node scripts/responsive-audit.mjs --route /pricing
```

It signs up a throwaway account, answers onboarding, creates a project, walks
all fourteen routes and deletes the project on the way out. Exit code is the
number of routes with faults, so CI can hold this line later.

## The first run found nothing, and that was the first bug

Every protected route reported the same two faults — a 20px `← Back` and a 20px
`Skip for now`, on `/dashboard`, `/settings`, `/learn`, `/storyboards`,
`/exports`, `/projects/new`, both project routes. Neither control exists on any
of those pages. They are onboarding's.

A freshly-registered account has not answered the four questions, so
`ProtectedRoute` sends it to `/onboarding`, and the audit was measuring the same
wizard nine times over while printing eight other route names beside it. It now
`PUT`s `/auth/preferences` for the throwaway account before it starts.

Worth stating plainly because the failure mode is the dangerous one: it reported
faults, so it did not look broken. It looked like a working audit of pages it
had never loaded.

## What the real run found

### One header, eight pages

    header scrollWidth   610 px   in a 375 px viewport

| Piece | Width |
|---|---|
| `BAAKHAPAA` wordmark | 129 px |
| Projects · Learn · Settings | 175 px |
| ⌘K Search · New project · avatar | 189 px |
| padding and gaps | 117 px |

343 px of usable width, 610 px of content. Below `md` the header now drops the
wordmark, replaces the `New project` label with a `+`, and hides the ⌘K hint:

- **The wordmark is 129px — 38% of the screen — for a link to `/dashboard`,
  which is what the `Projects` tab beside it already does.** It is the only item
  in the bar that costs width and carries no function a neighbour does not.
- **⌘K is a keyboard shortcut and a phone has no ⌘.** The palette itself is not
  lost: it is now the first item in the account menu, below `md` only.
- **`New project` becomes a `+`** with an `aria-label`, so the primary action
  stays on the surface rather than going behind a menu. This is the one place
  the Day 2 rule needed a judgement rather than an application: navigation is
  not "used while writing", but on a phone the bar's whole job is navigation, so
  the three destinations stay and the brand goes.

Result at 375px: 610 → fits, nothing scrolls sideways.

### A 2px slider

`/projects/new`, the runtime control:

    input[type=range].custom-slider    height: 2px

The 12px gold thumb is drawn overflowing a 2px element, and pointer events stop
at the element box. On a laptop you aim at the thumb with a mouse and never
notice. On a phone you have to land a thumb on a hairline, which means the
runtime slider was undraggable on the device most of this market uses.

The 2px line is now the *track* inside a transparent 24px element. Nothing about
the drawing changed.

### Small targets — WCAG 2.2 SC 2.5.8 wants 24×24 CSS px

Eleven controls were under it, from 17px (`Show password`, `↻ Refresh`) to 23px
(`Create one`, `Sign In`, the pricing wordmark).

Growing them would coarsen a layout that is right on a laptop to fix a problem
that only exists under a thumb, so `.tap` in `index.css` hangs the missing hit
area off a pseudo-element instead: the control stays exactly the size it looks,
and a thumb gets its 24px. It stretches vertically only, so in a row of controls
it cannot steal a neighbour's clicks.

Applied to: the password visibility toggle, `Create one`, `Sign In`, the Terms
and Privacy links on sign-up, the pricing wordmark and its `Back to Dashboard`,
onboarding's `← Back` and `Skip for now`, setup's `← Projects`, the Patterns
tab's `↻ Refresh`, and the Pen's *walk me through a whole scene*.

### Both auth pages scrolled sideways below 375px

    form panel   368 px   on every viewport narrower than 368

A flex item defaults to `min-width: auto`, so the panel refused to shrink below
its content and the width was a constant regardless of the screen. `min-w-0`
plus `px-5 sm:px-6`.

This was invisible at 375px and is the reason the run was repeated at 360 —
**360 is the common low-end Android width and is most of this market.** A pass
that only ever runs at one width finds only that width's bugs.

## What this does not prove

- **CSS is not in the unit tests.** `vite.config.js` sets `css: false` for
  vitest, so every breakpoint above is verified by this script in a real browser
  or not at all. Two things were pinnable and are pinned in `TopNav.test.jsx`:
  the menu's search item, and the `aria-label` that is the only name the `+`
  button has.
- **Two things the script cannot see** are collisions that do not overflow, and
  whether any of this is usable. Both are Day 5, on the device.
- **The audit checks two properties.** Contrast, text that is too small to read,
  and a control that is 24px tall and 8px wide all pass it.
